# 体格检查即时语音反馈设计

日期：2026-09-21

## 目标

在腹部触诊中，学生松开鼠标后立即看到患者反应并听到对应语音。触诊反馈不等待大模型或现场 TTS 请求，也不因语音服务异常阻塞本地教学反馈。

## 已确认的交互

- 按下腹部区域：立即显示按压状态、触点和患者痛苦表现。
- 松开鼠标：在本地根据区域、按压时长和教学演示状态计算压痛或反跳痛，立即更新文字、表情和检查记录。
- 按压不足 1 秒：使用压痛反馈。
- 持续按压至少 1 秒后松开：使用反跳痛反馈；阳性教学示例播放剧烈疼痛，病例本身的阴性反跳痛播放无明显反应。

## 语音方案

体格检查只使用预定义的短反馈语句，不调用聊天模型：

- `tender`：这里有点疼。
- `rebound-positive`：松开时剧烈疼痛。
- `normal` / `no-rebound`：这里没有明显不适。

进入体格检查页面时，使用当前患者的 `voice_id` 并行预生成这几句音频。客户端缓存按以下字段区分：

`patientId + voiceId + text + emotion + speed`

松开鼠标后优先播放已缓存音频。预生成失败时仍然立即显示本地文字和表情，并提供语音重试路径；不回退到浏览器系统语音，避免音色突然改变。

## 患者音色配置

患者病例提供自己的语音配置，体格检查和问诊共用该配置，但不共用播放队列：

```ts
voice: {
  provider: 'coze',
  voiceId: string,
  defaultEmotion: 'neutral',
  speed: number
}
```

新增患者只需增加病例和 `voiceId`，不修改体格检查组件。

## 范围

本次只改体格检查的即时反馈和语音缓存链路。问诊的模型流式输出和逐句 TTS 作为独立后续任务，不阻塞本次触诊实现。

## 验收标准

1. 松开触诊区域后，文字、表情和记录在同一交互周期内更新。
2. 已预缓存语音无需等待新的网络请求即可播放。
3. 三种固定反馈分别使用当前患者的 `voiceId`。
4. 语音服务失败不影响本地触诊反馈。
5. 现有压痛、反跳痛和教学演示测试全部通过。
