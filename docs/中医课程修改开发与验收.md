## 处置标准配置

文件：`server/treatment-rubric.json`。当前 `basis: "case_reference"` 将《诊治病例》王旭的处置和用药表转为练习对照项。该模式独立于下述教师审核模式，`approved` 仍为 `false`。它只评价处置与用药，依据为每条原表出处；不把未列方案或原表未给出的临床条件视为明确错误。

如以后另用教师审核模式，录入时需要填写：

- `caseId`：当前为 `wang-xu`。
- `version`、`approvedBy`、`reference`：标准版本、审核教师、出处。
- `approved`：教师确认后才设为 `true`。
- `required`：必须满足的条目。
- `forbidden`：明确错误的条目。
- `allowed`：其他可接受条目。
- `exhaustive`：教师确认标准覆盖整个提交范围后才设为 `true`。

三类条目均使用 `id / label / target / accepted / reason / reference`。`target` 为 `treatment`、`medication` 或 `diagnosis`。`accepted` 是教师批准的完整表述数组；处置比较项目正文，诊断比较每条诊断正文，用药比较“药名；途径；剂量”的完整组合。空白与常见标点会归一化；不做关键词式的临床正确性推断。

标准已审核、完整覆盖、必需条目满足、没有错误或未覆盖表述时才通过。明确错误或必需项遗漏返回需要修改；新表述和未覆盖方案进入待教师确认。未使用且未改动类别的六个预置空行可保留，定义统一在 `shared/treatment-presets.json`。新行或修改过的处置行必须填写类别与项目，有内容的用药行必须填写药名、途径和剂量。

接口：`POST /api/treatment-evaluation`，提交 `{ caseId, diagnosis, plan }`。标准由服务端读取，学生请求中的审核或通过字段不起作用。该接口仅返回本轮评价，不新增数据库或云端存档。

## 可选 AI 辅助核对

沿用已有 `OPENAPI_BASE_URL / OPENAPI_TOKEN`，另在本地 `.env` 配置 `EVALUATION_BOT_ID`，使用独立评价机器人。患者机器人继续使用 `PATIENT_BOT_ID`。

只有教师标准已审核时才调用评价机器人。它只能返回以下结构的逐字引用：

```json
{"notes":[{"checkId":"已有检查项ID","studentQuote":"该项学生原文的片段，可为空","referenceQuote":"该项依据或原因的原文片段"}]}
```

服务端检查引用是否真实存在。自由结论、摘要、编造的引用、未知检查项和不合格式结果均丢弃；AI 失败不影响已完成的规则检查。页面标注为 AI 辅助核对引用，规则状态不会被模型改写。此路径已用模拟上游验证，尚未配置并验证真实评价机器人。
